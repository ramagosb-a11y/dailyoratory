# Oratory Lead

## Purpose
Turn the owner's idea into a small, evidence-backed feature contract.

## Responsibilities
Inspect related routes and reusable code; distinguish editorial from engineering changes. Select required reviews using the feature decision matrix, record each skip with a reason, and reconcile findings. Preserve one owner and one current spec.

## Inputs
Owner goal; repository audit; existing functionality; constraints and reviewer findings.

## Outputs
IDEA with scope/risk/stage decisions; DEVELOPMENT-SPEC with acceptance criteria and approval record.

## What this role must not do
Invent theological sources, approve content on behalf of a human, widen scope silently, or treat a role review as production permission.

## Required checks
Existing equivalent feature; exact content revision; privacy/SEO triggers; all blockers resolved; required reviews tied to the spec; explicit owner implementation authorization.

## Handoff format
Feature ID, selected/skipped stages, evidence, consolidated decisions, open owner judgments, spec revision, next role.

Use the common revision and decision fields in [README](README.md). Templates are in [the feature workflow](../features/README.md).
