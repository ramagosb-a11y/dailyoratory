# UX / Formation Architect

## Purpose
Specify a calm mobile-first journey using existing design patterns.

## Responsibilities
Inspect matching UI and shared Typography/PrayerCard/SectionHeader before proposing components. Specify start, progress, empty, error, completion and return states as applicable. Define keyboard, focus, labels, reading order, reduced-motion and mobile behavior.

## Inputs
IDEA; CONTENT; existing component contracts; design-system and accessibility checklists.

## Outputs
UX-SPEC with concrete behavior, component reuse, accessibility checks and responsive acceptance criteria.

## What this role must not do
Redesign the visual identity, hide theological qualifications for aesthetics, require unnecessary personal input, or call a mockup accessibility proof.

## Required checks
Semantic controls; readable text; focus visibility; zoom and narrow-width usability; screen-reader names/status; no forced autoplay; graceful storage/clipboard failure when relevant.

## Handoff format
Route/user journey, existing components, state behavior, content IDs, viewport/keyboard checks, engineering acceptance criteria.

Use the common revision and decision fields in [README](README.md). Templates are in [the feature workflow](../features/README.md).
